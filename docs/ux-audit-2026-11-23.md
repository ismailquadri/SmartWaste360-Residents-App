# LAWMA 360 — Resident experience audit

**Date:** 23 November 2026  
**Framework:** Nielsen’s ten usability heuristics, plus accessibility/inclusion and offline resilience.  
**Scope:** Welcome and setup; Home and scenario switching; Wallet/top-up/room settlement/USSD; Bins and bag handoff; Activity and clean-up checks; Report, voice and live video; Profile, cases and reset; menus and sheets.

## Executive summary

The app has useful resident-specific safeguards: payment review, insufficient-balance blocking, batch settlement, readable QR codes, confirmation before reporting/reset, and media deletion undo. The largest remaining problems are **trust and clarity**, not decorative styling: some demo screens imply verified anonymity, delivered evidence, live telemetry or operational payments that the local demonstration does not establish.

This is a **heuristic review**, not WCAG certification, legal advice or a production security assessment. No critical failure was demonstrated. High-priority findings should be addressed before inviting residents to rely on the service.

## Prioritized findings

### High — unsupported whistleblower protections
The Report screen says “Zero-Knowledge Anti-Retaliation Vault,” EXIF/IMEI removal and cryptographically separated identity. The demo helper uses a deterministic non-cryptographic phone hash and sets a metadata-clean flag; the ticket remains in the resident’s local model. This does **not** establish anonymity or metadata removal.

**Recommendation:** Clearly label these as unimplemented/unverified demo protections. Before production, implement actual metadata removal, identity separation, a threat model and security review. Do not encourage sensitive real-world tips on the strength of the current claims.

### High — evidence is not uploaded with the case
Report submission records attachment names/types in a text note. Audio/video/photo bytes are not passed to the store’s local report action. Media URLs are then released. Local case creation is not proof that a collector or LAWMA received evidence.

**Recommendation:** Say “Saved locally as a demo case; files were not uploaded.” A production flow needs upload acknowledgement, retry/error states and retention until receipt is confirmed.

### High — offline draft is not an offline application
During an open session, turning the connection off still allows text drafting and displays a saved-local status. Reloading offline failed with `ERR_INTERNET_DISCONNECTED`. Saved text can be recovered once the app loads again; media cannot.

**Recommendation:** Describe this scope precisely. Add a cached application shell and durable media storage only if full offline reload/restart support is intended.

### High, improved this turn — sheet focus containment
Before this turn’s update, Tab escaped payment sheets and focus could return to the document body after closing. The shared sheet now uses the accessible dialog primitive, contains keyboard focus and restores the opening control. This also protects the new language chooser. Retest nested dialogs and real screen readers before certification.

### Medium — setup cannot go back
Profile → address → collector is model-driven on a single screen. Address and collector setup do not provide explicit Back controls. Browser Back is not an equivalent step-navigation system.

**Recommendation:** Add Back with retained inputs so residents can correct a name, phone or address without restarting.

### Medium — USSD/payment ambiguity
Selecting USSD during top-up opens a simulated-credit review. The separate USSD sheet opens a phone link. Legacy room shortcuts use a different base code.

**Recommendation:** Separate “Simulate top-up” from “Dial USSD,” verify carrier/service support, and never treat opening the dialler as successful payment.

### Medium — small introduction targets
Intro dots were observed at 6×6 and 32×6 CSS pixels, close together. Visual dots can remain small, but their tappable areas should be larger.

**Recommendation:** Use at least 44×44 touch areas and a complete keyboard pattern or simple labeled slide buttons.

### Medium — legal and service promises need verification
Court/tenancy rules, PSP assignment, POS voucher validity, bounty values and carrier availability are presented as operational facts in a simulation.

**Recommendation:** Distinguish illustrative rules from verified legal/service guidance; provide authoritative references and an escalation route. Keep statutory wording intact during translation.

### Medium, improved this turn — interface language coverage
Previously, only the voice assistant had dialect controls; the rest of the interface was English. The new persistent selector localizes resident labels, instructions, statuses, payment reviews and dialogs in English, Nigerian Pidgin, Yorùbá, Igbo and Hausa. Stored values, identifiers, QR codes and resident-written statements remain unchanged. Interface language initializes the voice dialect, while the resident can still choose a different speaking dialect.

**Remaining validation:** Native-speaker review of all generated translations, particularly legal, payment and privacy wording. Generated interface translations are not certified legal translations or proof of speech recognition accuracy.

### Low — handoff simulation disclosed late
Pass guidance initially describes a crew app and immediate verification; the explicit simulation message appears after starting handoff.

**Recommendation:** Disclose “Simulated crew handoff” before the resident starts, and label resulting verification as a demo outcome.

## What was not changed by this audit

The audit does not activate real payments, upload evidence, guarantee anonymity, add an offline application shell, amend statutory business rules or authenticate a production caretaker. Those findings remain recommendations rather than silently expanding this request into production infrastructure work.

## Verification and limitations

- Source-backed findings were checked against current resident model and screen code.
- Browser audit used the real public demo journey, including Wallet, Report and setup, at a phone-sized viewport.
- Language switching, persistence, translated wallet/report/profile/menu controls, modal keyboard behavior and frame boundaries passed across all five languages at 390×844 mobile and 737×991 tablet sizes. Typed top-up amounts retained focus; payment reviews remained labeled demo; resident-written report text survived reload unchanged. Nested menu/language dialogs contained Tab focus and restored their opening controls on Escape.
- All 57 regression tests passed. The final 915-entry catalogue passed placeholder/coverage checks, and all six routes, side menus and reset overlay passed the existing frame-boundary checker after the complete catalogue was saved.
- Camera/microphone tests use simulated devices; real iOS/Android hardware, carrier USSD sessions, legal enforceability, agency receipt, security protections and screen-reader certification are not established.

**Recommended next pass:** truthful demo boundaries → setup Back controls → USSD consistency → touch-target review → native-speaker translation review → production delivery/offline/security design.
